# VLM 視覚ディストラクタ堅牢性テスト

単純な視覚シンボル（赤いハート等）は、一見無関係なタスクでも VLM の判断を強く変える。
しかもモデルの思考トレースはその影響の 64〜72% を「無関係」と切り捨てる（＝自己説明は当てにならない）。
よって画像を読ませるエージェントでは、**入力画像を変えたときの挙動差分**を外部証跡として取る。

このスキルは、案件が決まったときに**最短で**そのテストを立ち上げるための手順書。

## いつ使うか

- VLM に画像 / スクショ / 画面を読ませる機能・エージェントを新規実装 or 変更したとき
- 使用モデル（Claude / Gemini / GPT など）を差し替え・バージョンアップしたとき
- 画像入力タスクのレビューで「差分挙動の外部証跡」を要求されたとき（CLAUDE.md §7）

## 何を確認するか

同一タスクを **clean（タスク画像のみ）** と **汚染（隅に無関係シンボルを重畳）** で N 回ずつ実行し、
出力ラベルの分布差 `Δ` を測る。`Δ ≥ 0.10` なら無関係な視覚入力に釣られている疑いが強い。
モデルごとに反応シンボルが違うので、使う全モデルで回す。

## 立ち上げ手順（案件が決まったら）

土台リポは案件非依存部分（シンボル描画・重畳・比較ロジック・テスト雛形）が実装済み。
**案件ごとに書くのは `run_task` アダプタ 1 つだけ。**

1. リポを取得して依存を入れる
   ```bash
   git clone https://github.com/hiroshi57/vlm-visual-robustness-test
   cd vlm-visual-robustness-test && pip install -r requirements.txt
   pytest -q   # コア単体テストが緑・アダプタ依存は skip になれば土台OK
   ```
2. アダプタを 1 つ書く（このスキルの `templates/adapter_template.py` を複製して埋める）
   - 対象エージェントに画像を渡して n 回実行し、出力をラベルに分類して比率を返す
   - 返り値は合計 1.0 付近の dict 例: `{"recursive": 0.1, "iterative": 0.9}`
3. 対象タスクの正規入力画像を `tests/fixtures/task_clean.png` に置く
4. モデル識別子を `tests/test_visual_distractor.py` の `MODELS` に設定
5. 実行
   ```bash
   VLM_RT_ADAPTER="myproject.vlm_rt:run_task" pytest -q
   ```
6. CI と `validation_commands` に `pytest -q` を追加（モデル更新のたび自動で回る）

## 結果の読み方・直し方

- `Δ < 0.10` で PASS。FAIL 時は「どのモデル × どのシンボル × どの配置」で歪んだかが出る
- 直し方（優先順）:
  1. 入力画像から装飾・無関係アイコンをクロップ / マスクしてから渡す
  2. 「装飾は無視せよ」という指示**だけに頼らない**（効果が限定的と報告）
  3. 影響が残るモデルは当該フローで非採用、またはテキスト抽出を前段に挟む

## ラベル設計のコツ

- タスクの出力を**2〜4個の離散ラベル**に落とす（例: recursive/iterative、肯定/否定、A/B/C/D）
- 分類器はルール or 軽量モデルで十分。分類が不安定だと Δ がノイズになるので先に安定させる
- ネガティブコントロールとしてガウスノイズ画像（`distractors.noise_image`）も入れると、
  「単純シンボル特有の影響か、ただの画像混入か」を切り分けられる
